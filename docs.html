Scope Creep Detector for Jira — Documentation

Last updated: October 15, 2026

Scope Creep Detector helps Jira teams identify when an issue grows beyond its originally approved requirements. It compares the current issue description against a saved baseline and highlights newly introduced requirements and their estimated impact.

1. What the app does

Scope Creep Detector can:

  • Save an approved Jira issue description as a baseline
  • Compare later edits against that baseline
  • Identify newly added requirements
  • Classify additions by impact
  • Show requirement-count growth
  • Calculate a scope-change score from 0 to 100
  • Distinguish harmless wording changes from meaningful scope expansion
  • Allow teams to update the baseline when changes are formally approved

2. Installation

Scope Creep Detector is installed through the Atlassian Marketplace by a Jira site administrator.

After installation, the app appears within supported Jira issue views.

3. Setting the initial baseline

  1. Open a Jira issue that contains the agreed requirements in its description.
  2. Locate the Scope Creep Detector panel.
  3. Review the current issue description.
  4. Select Update baseline to save the current description as the approved baseline.

The saved baseline becomes the reference point for future scope comparisons.

4. Re-scanning an issue

When the Jira issue description changes:

  1. Save the updated Jira issue.
  2. Open the Scope Creep Detector panel.
  3. Select Re-scan.
  4. Review the scope score, requirement count, and any newly detected requirements.

5. Understanding the score

0 — No material scope change

The wording may have changed, but no meaningful new requirement was detected.

Low-impact scope change

A small additional requirement has been detected. Teams should review the change, but it may not materially affect delivery.

Possible scope expansion

One or more meaningful requirements have been added and should be reviewed before work continues.

High scope-creep risk

Several material requirements have been added compared with the saved baseline. The issue should be reviewed before additional work is accepted.

6. Example

Saved baseline:

Users should be able to export customer records as a CSV file.

Low-impact addition:

The export should use UTF-8 encoding.

Scope Creep Detector identifies this as an added requirement while keeping the overall risk score relatively low.

Major expansion:

If PDF export, scheduled exports, email delivery, approval workflows, role-based restrictions, expiration rules, and audit logging are added, the app detects each new requirement and assigns a much higher scope-risk score.

7. Updating an approved baseline

If the new requirements are formally approved and should become the new scope:

  1. Confirm the Jira description contains the approved requirements.
  2. Select Update baseline.
  3. The current description becomes the new reference point for future comparisons.

8. Data handling

Scope Creep Detector runs on Atlassian Forge. Saved scope baselines use Atlassian-hosted Forge storage.

The app does not send Jira issue content to an external AI service, advertising platform, or independent UhuruLabs application backend.

See the Privacy Policy and Security Policy for more information.

9. Limitations

Scope Creep Detector is a decision-support tool. Its scores and classifications should be reviewed by the project team and do not replace contractual, financial, project-management, or professional judgment.
