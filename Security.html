Security Policy — Scope Creep Detector for Jira

Effective date: October 12, 2026

This Security Policy describes the security approach used by UhuruLabs for Scope Creep Detector for Jira (“the App”).

1. Hosting and infrastructure

Scope Creep Detector is built on Atlassian Forge. App execution and persistent storage use Atlassian-hosted Forge services. The App does not operate a separate UhuruLabs application server for processing Jira issue content.

2. Data handling

The App accesses Jira issue descriptions as required to perform scope-change analysis and stores saved scope baselines using Atlassian Forge storage.

Jira issue content is not sent to an external AI service, advertising platform, external analytics service, or independent third-party processing backend.

3. Access permissions

The App requests only the Atlassian permissions required to provide its functionality. Scope Creep Detector does not require customers or end users to provide Atlassian Personal Access Tokens, account passwords, API secrets, or other shared credentials.

4. Application licensing

Paid production functionality is subject to Atlassian Marketplace licensing. The App checks the license state provided by Atlassian and restricts paid functionality when an active license is not present.

5. Logging

The App does not intentionally log Jira issue descriptions, saved baselines, passwords, access tokens, or other customer secrets. Operational logging is limited to information needed to operate and troubleshoot the App.

6. External integrations and egress

Scope Creep Detector does not expose a remote REST API and does not require external service integrations for its core functionality. Customer Jira content is not intentionally transferred outside Atlassian-hosted Forge services.

7. Vulnerability reporting

If you believe you have discovered a security vulnerability in Scope Creep Detector, please report it privately to UhuruLabs before publicly disclosing the issue.

Security contact:

uhurulucas@gmail.com

Please include a description of the issue, reproduction steps where possible, and any relevant technical details. Do not include passwords, API tokens, or other secrets in vulnerability reports.

8. Security response

UhuruLabs will review reported security issues and prioritize remediation based on severity and impact. Material security issues will be addressed as promptly as reasonably possible.

9. Changes to this policy

This Security Policy may be updated as the App or its security practices evolve. The current version will remain available at this URL.
